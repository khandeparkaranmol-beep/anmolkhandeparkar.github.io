Research question / Autonomous game-playing AI

Can an agent learn
an unfamiliar game
by learning its world?

Give it a new 2D platformer, a limited opportunity to explore, and the ability to retain what it learns across attempts. Can it discover how the game works—and use that knowledge to play reliably?

That is the research goal. Mario is the development environment; reliable adaptation to unseen games is still to be demonstrated.

01 / Choosing the brain

Why a world model
instead of an LLM?

The core question is physical: “If I hold right and jump now, where will I land?” I want the agent to learn that relationship from what actually happens when it acts.

An LLM-centered agent

Reason about what to do.

An LLM could interpret a scene, propose a plan and call a control tool. That is useful for language, instructions and high-level strategy. But those abilities alone do not establish accurate predictions of this game’s momentum, collisions or jump timing.

This agent’s approach

Learn what actions cause.

The world model learns from sequences of observations, actions and outcomes. It predicts how the environment changes, giving the policy an internal environment in which to learn before taking another real action.

The design hypothesis

A model trained on action consequences could provide a useful foundation for adapting to unfamiliar mechanics. This project tests that hypothesis; it has not established an advantage over an LLM agent in a matched comparison.

What makes it an agent?

It observes the game, chooses and executes controls, receives feedback and updates its behavior toward a goal. Predicting a future frame is one component of that loop.

What does “brain” mean here?

The world model supplies predictive state and imagined experience. An actor chooses actions, a critic estimates their value, and replay retains experience for learning. Together they form the decision-making system.

02 / Why custom?

To study the learning,
I need control of the system.

I’m building a compact implementation around the questions I want to test: what the agent remembers, how its predictions shape behavior, and what changes when it enters a different game.

Built around explicit experiments.

I can change the observation model, memory handling, actor training or replay behavior—and compare the change against a frozen checkpoint. The failure can be traced to a component rather than hidden behind a model API.

Designed beyond one game.

Game-specific interfaces sit in adapters. The learning stack operates on observations, actions, rewards and episode boundaries. Mario and CoinRun exercise that separation; cross-game transfer remains an open test.

Memory is part of the design.

A new attempt and a new task are different events. The implementation separates those resets so I can test whether retained experience helps the agent learn across attempts.

Grounded in existing research.

“Custom” means my implementation and experimental choices. The current architecture follows the Dreamer approach to learning behavior in imagination; it is not a claim of inventing a new model family.

03 / Inside the current architecture

A loop that learns
from its own experience.

A compact Dreamer-style implementation connects a visual world model, an actor–critic policy and persistent replay. The agent learns from screen observations and the environment’s reward.

01 / OBSERVE

Read the screen.

Encode the image and combine it with recurrent state to keep track of what has happened.

02 / MODEL

Learn consequences.

Predict future observations, reward and whether the episode continues, conditioned on actions.

03 / IMAGINE

Train in imagination.

The actor and critic learn from trajectories generated inside the learned world model.

04 / ACT

Return to the game.

Execute an action, record the actual outcome and use sequence replay to update the system.

Real experience → persistent replay → world model + actor + critic → next interaction
Memory

A retry is different from a new task.

Episode resets and task resets have separate semantics. Evaluations compare retained context against reset context to check whether experience actually helps on the next attempt.

Environment boundaries

Even the last frame matters.

The CoinRun adapter auto-resets at an episode ending. Its reset image must not become a false terminal target. Missing terminal images are masked while their rewards and termination signals remain trainable.

06 / Where it stands

The system is built.
The capability is still being earned.

The ambition is an agent that learns action consequences and adapts through experience. Reliable completion and useful adaptation remain open goals.

Implemented and exercised

  • Visual dynamics, recurrent state and imagined actor–critic learning.
  • Online collection, replay and recoverable training checkpoints.
  • Frozen-model comparisons and reset-versus-retained-memory evaluations.
  • A second-game adapter with verified terminal-image handling.
Current investigation

Test whether leading idle actions in human demonstrations contribute to the stalled policy. Keep the learning history intact, change only the initial training targets, and judge the result by actual gameplay.
